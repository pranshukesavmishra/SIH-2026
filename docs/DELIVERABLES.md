### Nothing new to buy after the CAD audit
The clearance sweep changed the geometry but **not the shopping list**.
The pan platform grew from 34 mm to 60 mm — cut it from the **second
sheet in the acrylic pack of 2** you are already buying. Both encoder
arms are M3 brass standoff plus an acrylic offcut, from the ₹150
assortment. **Total stays ₹6,709.**

### Three that stop the build dead
1. **Magnets must say DIAMETRIC.** Axial looks identical, reads a constant, both feedback axes dead. Spin one next to a phone compass: the needle must flip twice per rotation.
2. **Buy the 100 µF caps.** ₹20. Without them both A4988s die on first power-up.
3. **Set A4988 Vref to 0.5–0.6 V before attaching a motor.** Needs the multimeter; there is no way to do it by eye.

**Travel is mechanically limited — soft-limit it in firmware.**

| Axis | Limit | Stopped by |
|---|---|---|
| Pan | ±120° | tilt bracket vs the fixed encoder post |
| Tilt, down | +20° | **the pan platform** (the base plate is 9° further) |
| Tilt, up | −40° | nothing in range |

The benchmark's widest pattern asks for ±35° of pan and a few degrees
of elevation, so none of this costs us anything — but they are real
limits of the layout, measured by `tools/cad/check_clearance.sh`, not
estimated.

**Do not print the head standoff.** Use an M3 brass standoff from the
assortment. In PLA it droops 28.5 px and resonates at 53 Hz — sitting on
the 47 Hz platform mode the benchmark injects.

### Where we stand against the spec — honestly

**Met (11):** camera resolution, FOV, update rate, pan/tilt speed, target
shape and size, ≥4 motion patterns including Figure-of-8, all three noise
types with salt-and-pepper at the specified 10%, camera jitter, linear
platform motion, all five atmospheric conditions, MP4 input bypassing the
PTZ camera.

**Open (3):**

| Row | Spec | Ours |
|---|---|---|
| Acquisition time | ≤ 2 s | 25.3 s → **3.53 s** |
| Tracking error (median) | ≤ 10 px | 2,367 → **170 px** |
| Processing speed | ≥ 20 FPS | **9.2 FPS** |

The arrows are before → after our own fix, **both measured with the full
specified disturbance present**. A constant-velocity platform drift is a
ramp, and a PD loop has finite steady-state error to a ramp — wrong loop
order, not bad tuning. Adding a second integrator (type 2, leaky) cut
acquisition 7× and median error 14×. It is implemented and shipped. It is
not yet enough, and the slide says so.

## 4. Run it

```sh
fsoc-pat scenarios/ps26169_benchmark.yaml          # GUI
python -m fsoc_pat.runner scenarios/ps26169_benchmark.yaml   # headless report
python -m fsoc_pat.runner scenarios/ps26169_benchmark.yaml --atmosphere fog
python -m fsoc_pat.hil.serve --video clip.mp4     # Benchmark-2 path
pytest tests/ -q                                   # full suite
```

`scenarios/ps26169_benchmark.yaml` encodes the evaluators' table and
nothing else. Every performance number we publish is measured on it.
